# ADR-0012: 资产空间与接口账本

- 状态：已接受
- 日期：2026-09-09

## 背景

真实授权测试很少是"一个全新目标从零开始"，更常见的是：同一家单位的多个站点、同一套小程序的多个入口、同一批资产被反复测试。此时最大的浪费是**重复劳动**——上一次已经枚举过的接口、已经确认无问题的路径，这一次又来一遍；而最大的风险是**覆盖盲区**——没人说得清"这个资产到底还有多少接口没测"。

项目（Project）这个粒度不够：项目是一次任务的容器，用完即弃，跨任务的资产记忆无处安放。

## 决策

引入独立于项目的**资产空间**，并以**接口账本**作为其结构化记忆：

1. **资产键**：`(target_kind, asset_ref)` ——web 用 host、小程序用 AppID、安卓用包名。项目创建时确定或从 `origin` 自动提取，可在项目间复用。
2. **账本表 `asset_endpoints`**：按规范化的 host 记账（method、path、来源项目、首次/末次出现、status）。**结论落图时自动登记**（从结论文本启发式提取接口并 upsert），无需人工录入。
3. **覆盖即提示**：新建同资产项目时，若账本已存在，自动注入一条**覆盖线索**（已发现/未测清单逐条）作为行动的起点——不是硬约束，而是让 agent 一开局就知道"哪些是已知、哪些是空白"。
4. **两类记忆分工**：**结构化账本**（确定性的已发现/未测，可查询、可统计）与**软性知识**（跨任务的经验结论，best-effort 检索）分开存放，互不冒充。
5. **资产聚合视图**：`GET /assets` 按资产键聚合项目、高危数、待审批数与接口覆盖（"接口 N/M 待测"），让"这个资产当前状态如何"一眼可见。

## 备选方案

- **只靠项目**：跨任务记忆为零，同资产重复枚举；覆盖盲区不可见。
- **全局单一接口表（不带资产键）**：host 之间接口语义不同，聚合会串味；且小程序/安卓目标没有 URL 形态，无法归入。
- **靠知识库（自然语言记忆）承载覆盖信息**：检索不确定、统计不可靠，无法回答"还有多少没测"。
- **引入外部资产管理/ASM 系统**：能力过剩，且数据要离开本机；单机零运维（ADR-0002）原则不符。

## 后果

- 优点：同资产多次任务之间形成积累，"测过什么"从记忆变成查询；覆盖缺口显式暴露，减少盲区与重复。
- 优点：账本自动登记让记账成本接近零，不依赖 agent 自觉遵守流程。
- 缺点：接口提取是启发式的，会有漏记与误记；status 的 verified/dismissed 语义目前预留，尚未与漏洞确认、人工验收完全联动。
- 缺点：资产键的规范化（是否含端口、大小写、www 前缀）需要长期保持一致，否则同一资产会被拆成多个空间。
