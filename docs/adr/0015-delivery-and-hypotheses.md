# ADR-0015: 以「交付质量 + 工作记忆 + 假设驱动」提升长任务价值

- 状态：**已接受**（P0-1 结论可交付性、P0-2 环境基线**已实现**；P0-3 假设驱动**设计中**）
- 日期：2026-09-09（**修订版**，取代同日"管理面三层"初版）
- 关联：ADR-0003（证据—行动图）、ADR-0011（审批闸门是产品边界）、ADR-0014（行动生命周期与阶段）

## 修订说明：为什么把初版方向改掉

初版提出"管理面三层"——资源账本（含**自动回收**）、产出经济学（**强制排序 + 自动止损**）、计划链（任务调度）。这些结论来自一次长任务（63 个目标的授权评测）的实测数据。

**使用者否决了这个方向，理由是对的**：Sharp 不是为跑测试而生的工具。评测场景优化的是「一定时间内拿最多分」，授权渗透优化的是「**不遗漏、打得深、说得清、可复用**」。用评测的效率指标驱动架构，会把工具优化成刷分机器。

被具体否决的三点：

| 初版主张 | 为什么否决 |
| --- | --- |
| 按产出**强制排序**优先级 | 真实场景里**目标不能换**，价值在于**深**而不是广。"刷简单目标"不但无意义，还会漏掉关键面。排序最多作为**建议**呈现给人 |
| **自动回收 / 自动止损**（占着不产出就踢掉、几轮无结果就放弃） | 这是把研究员的判断交给算术规则——可能在正要突破时被掐断；与 ADR-0011「边界优先」冲突 |
| 硬编码并发上限（"3 个槽位"） | 那是评测平台的规则。真实场景的稀缺资源是**授权时间窗、API 成本、并发限速**，性质与优先级都不同 |

因此本版**保留"给规划器补决策输入"的判断**，但把补的内容换成服务初衷的三件事。

## 背景（哪些实测证据仍然有效）

| 实测现象 | 重新解读 |
| --- | --- |
| 同一条网络预检被重复执行 **144 次** | ✅ **真问题**：每个行动是独立会话，上下文从零构建，"已确认的前提"被反复支付。真实项目里就是**重复侦察**，直接吃掉授权时间 |
| 空转证据占比 **69%**、单目标最多 **20 轮**零产出 | ⚠️ **部分是深挖的正常表现**（真实渗透本就该在一条线上反复推进），只有"反复做同样尝试"的部分才是浪费。不能用"无产出"直接判定该放弃 |
| 结论只有标题与描述、无复现证据 | ✅ **真问题**：交付物是报告，报告的价值取决于结论能否被复现——"不可验证的声称"会损害整份报告 |
| 多阶段依赖任务靠漫游式试探 | ✅ **真问题**：真实长链渗透比评测更依赖"我在哪一层、下一步依赖什么" |

## 决策

补三件事（都是"图上加层"，不动骨架：三进程 / 图作唯一真相源 / 审批闸门）：

1. **结论的可交付性**（已实现）：`vulnerabilities` 的四个字段构成"可复现四件套"（原始请求/响应、复现步骤、影响说明、定位），由 `finding_quality.py` 计算完备度，作为派生字段随响应返回；报告侧带 `evidence_quality` 并被要求把不完备结论标注为「⚠️ 证据不足待补充」。**让"证据不足"在交付前可见**，而不是靠生成报告的模型自己猜。
2. **环境基线**（已实现）：把"作业前提"（连通性、凭据有效性、可达性、工具可用性）与"探索结论"分开记账——`env_baseline` 表 + `{env_baseline}` 注入提示词 + 两条规则（信任基线、扩展基线）。前提确认一次、长期复用；**不混进证据链与报告**。
3. **未验证假设（Hypothesis）一等公民**（设计中）：让"我猜这里有 X"成为可记录、可派发、可结算的对象，行动可挂到假设上（"这一步是为了验证哪个假设"），规划器的主职责从"找线索"变成"**消灭未验证假设**"——这是真实渗透推进的本来逻辑。

并且**不引入 supervisor（观察者）agent**，理由与初版一致：

- 职责与 reason 重叠 → 两个"大脑"争一个决策权，冲突需额外仲裁层
- 每次调度多一跳 LLM → 长任务数百次调度，延迟与成本翻倍
- 与 ADR-0003「agent 之间不直接通信、只读写同一张图」冲突

替代做法：**算术交给确定性代码**（槽位占用、投入产出、停滞标记、候选排序都是可计算的），**判断题留给 reason**（这条路还有没有希望、要不要换向）。这样"观察者"的效果达到了，但没有新增角色。

## 备选方案

- **A. 新增 supervisor LLM 角色**：否决（见上）。
- **B. 只改提示词**（让规划器"记得沉淀前提、记得标注证据不足"）：否决。实测证明写在提示词里的规则不出效果——本次止损是**人工注入具体指令**后才发生的。边界不该交给模型自觉（与 ADR-0011 对审批闸门的论证同构）。
- **C. 保持现状 + 人工催**：否决。不可持续，且强依赖在场的人。
- **D. 按评测效率指标驱动架构**（初版方向）：**否决**——见"修订说明"。评测可以用来验证**执行可靠性**（能不能跑、崩不崩、恢复快不快），但不能用它的**效率指标**决定架构。

## 后果

- 优点：三件事都直接服务初衷——① 是"说得清"，② 是"不浪费授权时间"，③ 是"打得深"；都以"图上加层"实现，不动骨架、不破坏可追溯性与审批边界。
- 优点：可交付性判定是**纯函数**（可测、可解释），"为什么这条结论需要补证据"能给出一行理由，而不是"模型觉得证据不够"。
- 缺点：假设驱动要求规划器改变工作方式（从"找线索"到"消灭假设"），提示词与模型行为需要真实验证；假设层若被滥用会变成"假设刷屏"（需要人工可删改，与阶段同样的兜底）。
- 缺点：环境基线依赖 worker 主动写入——提示词里已给出创建指引，否则机制会空转（这一条已用测试固定：空基线时提示词必须包含创建方法）。
- 风险：这些机制的真实价值**在评测场景中验证不出来**（评测检验不到报告质量、积累复用、人工协作）。因此下一步验证应当放在**真实授权项目**上，而不是再跑一次靶场。
